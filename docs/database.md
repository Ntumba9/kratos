# KRATOS Database Design

PostgreSQL 17 is the system of record. This document defines the schema for
every phase. Tables marked **(P1)** and **(P2)** exist as migrations today; the
rest are designed here and are created by migrations in the phase indicated.

## Conventions

- **Primary keys**: `uuid` (UUIDv7, generated by the application, time-ordered
  for B-tree locality). Lookup tables (`roles`, `permissions`) use `smallint`
  identities since they are internal and never exposed in URLs.
- **Tenant key**: every tenant-owned table has `organisation_id uuid NOT NULL`
  → `organisations(id) ON DELETE CASCADE`, and every index used for listing
  starts with `organisation_id`.
- **Timestamps**: `timestamptz`. `created_at`/`updated_at` on mutable rows,
  `created_at` only on append-only rows.
- **Soft deletes** only where a business recovery path exists
  (`organisations`, `monitored_assets`). Security telemetry is not soft-deleted;
  it is removed by retention jobs.
- **Enumerations** are `varchar` + `CHECK` constraints (not native enums) so
  values can be added in a migration without `ALTER TYPE` locking issues.
- **Secrets**: never plaintext. Passwords: Argon2id. Tokens and credential
  secrets: SHA-256 digest (tokens) or HMAC-SHA256 keyed with `APP_KEY`-derived
  pepper (credentials), compared in constant time.

## Entity relationship overview

```
users ─┬─< organisation_memberships >─ organisations ─┬─< monitored_assets ─< monitoring_agents
       │            │                                  ├─< api_credentials
       │            └── roles ─< permission_role >─ permissions
       │                                               ├─< security_events ─< detection_results >─ detection_rules
       │                                               │         │                     └── model_versions
       │                                               ├─< incidents ─< incident_events >─ security_events
       │                                               │      ├─< investigation_reports
       │                                               │      └─< alerts
       ├─< personal_access_tokens                      ├─< audit_logs
       └─< sessions                                    └─< background_jobs
```

The application role `kratos_app` has `SELECT, INSERT` only — no `UPDATE`/`DELETE`.

### Framework tables (P1)
- `personal_access_tokens` — Sanctum; `tokenable` is a UUID morph; `token` is a SHA-256 digest; `expires_at` always set.
- `sessions` — database session driver so active sessions can be listed and revoked; `user_id uuid`.
- `password_reset_tokens` — hashed reset tokens, 60-minute expiry.
- `jobs`, `job_batches`, `failed_jobs` — `failed_jobs` is the Laravel-level dead letter store.
- `cache`, `cache_locks` — unused while Redis is the cache store; kept for fallback.

### `monitored_assets` (P2)
`id, organisation_id, name, asset_type CHECK(server|application|database|network_device|endpoint|cloud_service), hostname, ip_address inet NULL, environment CHECK(production|staging|development), criticality CHECK(low|medium|high|critical), tags jsonb, last_seen_at, created_at, updated_at, deleted_at`.

Partitioning by `occurred_at` (monthly, declarative) is the planned scale path
once volumes justify it; it is deferred so that unique constraints remain
simple during early phases.

### `event_outbox` (P2)
`id bigint identity, security_event_id uuid UNIQUE → CASCADE, organisation_id, available_at, published_at NULL, publish_attempts int, last_error, created_at`. Partial INDEX(available_at, id) WHERE published_at IS NULL. Transactional outbox (see ARCHITECTURE §5); not exposed through the API.

### `detection_results` (P3)
One row per piece of evidence (triggered rule, anomaly model, statistical
detector) for an event. Re-analysis deletes and re-inserts the event's rows in
one transaction, so replays never duplicate evidence.

| Column | Type | Notes |
| --- | --- | --- |
| id | uuid PK | |
| organisation_id | uuid → organisations CASCADE | Tenant scope |
| security_event_id | uuid → security_events CASCADE | INDEX |
| detector | varchar(24) | CHECK(rule, anomaly_model, statistical) |
| rule_key | varchar(64) NULL | For rule evidence |
| model_version_id | uuid NULL → model_versions SET NULL | |
| severity, category | varchar NULL | |
| score | numeric(6,2) | Detector-specific scale |
| explanation | text | Human-readable, deterministic |
| details | jsonb | Observed values, thresholds, feature contributions |
| created_at | timestamptz | INDEX(organisation_id, created_at DESC); partial INDEX(organisation_id, rule_key, created_at DESC) |

### `security_events` additions (P3)
`verdict` (CHECK benign | suspicious | malicious, NULL until analysed),
`threat_category`, `anomaly_percentile numeric(5,2)`, `analysis_summary text`,
`model_version_id → model_versions SET NULL`, `analysed_at`. `risk_score`
(added in P2) is now set by MIND. Partial indexes on
(organisation_id, verdict, received_at DESC) and (organisation_id, risk_score DESC).

## Phase 4 tables

### `incidents` (P4)
`id, organisation_id, reference varchar(24) (e.g. INC-000123, UNIQUE per org), title, summary, severity, status CHECK(open|triaged|investigating|contained|resolved|false_positive), assigned_to NULL → users, correlation_key varchar(128), first_seen_at, last_seen_at, resolved_at, resolution text, created_at, updated_at`.
INDEX(organisation_id, status, severity); partial UNIQUE(organisation_id, correlation_key) WHERE status NOT IN ('resolved','false_positive') — prevents duplicate open incidents for the same correlation.

### `incident_events` (P4)
`incident_id → CASCADE, security_event_id → CASCADE, linked_by CHECK(correlation|analyst), created_at, PK(incident_id, security_event_id)`.

### `investigation_reports` (P4)
`id, organisation_id, incident_id, version int, generator CHECK(deterministic|llm_assisted), observations jsonb, hypotheses jsonb, recommendations jsonb, timeline jsonb, severity_estimate, generated_by NULL → users, created_at`. UNIQUE(incident_id, version).

### `alerts` (P4)
`id, organisation_id, incident_id NULL, channel CHECK(in_app|email|webhook), status CHECK(pending|sent|failed|acknowledged), payload jsonb, acknowledged_by, acknowledged_at, created_at`.

### `response_actions` (P4)
`id, organisation_id, incident_id, action_type, parameters jsonb, status CHECK(proposed|approved|rejected|executed|failed), proposed_by NULL (NULL = system), decided_by, decided_at, decision_note, created_at` — every disruptive action requires `approved` by a human with `incidents.approve_response`.

## Phase 5 tables

### `monitoring_agents` (P5)
`id, organisation_id, monitored_asset_id, name, agent_version, platform, api_credential_id, status CHECK(pending|active|stale|revoked), last_heartbeat_at, last_metrics jsonb, registered_at, created_at, updated_at`. INDEX(organisation_id, status).

### `background_jobs` (P5)
Durable job status tracking independent of Redis: `id, organisation_id NULL, job_type, queue, subject_type, subject_id, status CHECK(queued|running|succeeded|failed|dead_lettered), attempts, last_error text, queued_at, started_at, finished_at`. INDEX(status, queued_at).

## Data retention policy

| Data | Default retention | Mechanism |
| --- | --- | --- |
| `security_events`, `detection_results` | `organisations.event_retention_days` (default 90), by `received_at` | `kratos:events:prune`, daily 03:15, 1 000-row chunks (implemented P2) |
| `incidents` and linked reports | Indefinite while open; 2 years after resolution | Scheduled job (P4) |
| `audit_logs` | 1 year (configurable, minimum 90 days) | Run as `kratos_owner` maintenance task, since the app role cannot delete |
| `sessions` | Session lifetime (120 min idle) | Laravel session GC |
| `personal_access_tokens` | Expiry (default 90 days) | `sanctum:prune-expired` scheduled daily |
| `failed_jobs` | 30 days | `queue:prune-failed` scheduled daily |
